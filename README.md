# Batter Beats

Walkup music for baseball and softball games. A web app you add to your
phone's home screen, served from your own server.

- **Game mode:** the lineup as big buttons. Tap a batter: the announcer says
  "Now batting, number 12, Ava" and their walkup song comes in under the voice.
  Tap again to fade it out. The next batter is marked on deck.
- **Works at the field without signal:** each phone keeps the teams it needs
  (the short clips and announcements, roughly 15 MB per team).
- **Clips are cut losslessly:** MP3 frames are copied, never re-encoded. Gain
  is set in 0.5 dB steps (1.5 dB steps written into the file the way MP3Gain
  does, the rest applied on the phone), with bass, treble, volume and a
  curved fade-out.
- **Announcer:** generated by [Kokoro](https://github.com/remsky/Kokoro-FastAPI),
  a free voice engine that runs on an ordinary CPU, with a "say it like this"
  spelling for hard names.
- **Between-innings playlist** for each user, shuffled, fading out when a
  batter is tapped.
- **Accounts and roles** (user, editor, admin) created by an admin; backups
  of everything as one file.

## Running it

You need a server with Docker (for example with Portainer) and an https
address in front of it. Adding the app to a phone's home screen and keeping
teams for offline use only work over https.

### 1. Start the stack

Use [docker-compose.yml](docker-compose.yml). In Portainer: **Stacks → Add
stack**, paste the file, then:

- set `ADMIN_PASSWORD` (used only the first time, to create the first admin);
- change the published port `8090` if it's taken.

The stack has two containers: the app (`ghcr.io/yesterdayforgotten/batter-beats`,
with everything it needs built in) and the voice engine (`kokoro`). All data
(database, songs, clips, announcements) lives in the `batter-beats-data`
volume; updating the containers never touches it.

### 2. Put https in front of it

Point your reverse proxy at the app's port. For Apache 2.4.47 or newer:

```apache
<VirtualHost *:443>
    ServerName walkups.example.com
    SSLEngine on
    SSLCertificateFile    /etc/letsencrypt/live/walkups.example.com/fullchain.pem
    SSLCertificateKeyFile /etc/letsencrypt/live/walkups.example.com/privkey.pem

    ProxyPreserveHost On
    RequestHeader set X-Forwarded-Proto "https"
    ProxyTimeout 300
    ProxyPass        / http://DOCKER_HOST:8090/
    ProxyPassReverse / http://DOCKER_HOST:8090/
</VirtualHost>
```

(`sudo a2enmod ssl proxy proxy_http headers`.) The app trusts proxies on the
local network for the https information; change `TRUST_PROXY` if yours is
elsewhere.

### 3. First sign-in

Open the https address and sign in as `admin` with the password you set.
Then, under **Admin**:

- **Users:** add an account for each person. Regular users run game mode and
  build their own playlist; editors also manage teams, players and songs;
  admins also manage users, the announcer voice and backups.
- **Announcer voice:** listen to the voices and choose one.

### 4. On each phone

1. Open the address in Safari (iPhone) or Chrome (Android) and sign in.
2. Add it to the home screen (Safari: **Share → Add to Home Screen**; Chrome:
   **⋮ → Add to Home screen**). On iPhone this matters: home-screen apps keep
   their stored teams, Safari tabs may lose them after a week.
3. On the **Teams** screen, turn on **Offline** for each team this phone
   needs, and wait for the tick.
4. On older iPhones, set **Settings → Display → Auto-Lock** to *Never* during
   games if the screen still dims.

### Updating

In Portainer, open the stack and **Update the stack** with **Re-pull image**
on. Phones show an **Update** button next to the version number when the
server has a newer version.

### Backups

**Admin → Backup → Download backup** saves everything (teams, players, songs,
clips, announcements, users, playlists) as one `.tar` file. **Restore from a
backup…** replaces everything with a backup's contents; what it replaced is
kept in the data volume's `tmp/before-restore-…` folder until the next
restore. Copying the data volume is a full backup too.

### Settings

| Variable | Default | What it does |
| --- | --- | --- |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | `admin`, random | First admin, created only when there are no users. A random password is printed in the log. |
| `PORT` | `8090` | Port inside the container. |
| `DATA_DIR` | `/data` | Where everything is stored. |
| `TTS_URL` | `http://kokoro:8880` | The voice engine. Empty turns the announcer off. |
| `TRUST_PROXY` | local network | Which proxies to trust for https detection. |

## Development

Requires Node.js 22, `ffmpeg` and `mp3gain`.

```sh
npm install
cp .env.example .env   # then edit .env
npm run dev            # http://localhost:8090, with hot reload
```

[Dockerfile.dev](Dockerfile.dev) builds a development container with these
tools and Claude Code; [PLAN.md](PLAN.md) records the design decisions and
the current status. GitHub Actions builds the production image on every push
to `main`.
